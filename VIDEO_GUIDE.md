# Short Video Explanation Guide

Recommended video style: use a PPT-style flow for the first 60-90 seconds, then show GitHub and code for proof. This is better than only explaining code because evaluators first need to understand the journey, then see evidence.

## Suggested 4-5 minute structure

1. Introduction (20 seconds)
   - Name, repository links, and what the portfolio contains.

2. What I built (60 seconds)
   - Mention mini projects 1-7 and exercises 1-41.
   - Say the work moves from basics to OOP, data analysis, Flask, and MQTT.

3. Implementation choices (90 seconds)
   - Calculator: while loop for repeated user choice.
   - Transaction manager: OOP inheritance, validation, logging, unit tests.
   - Data projects: pandas groupby/pivot/normalization instead of manual loops.
   - Flask: routes, templates, POST actions.
   - MQTT: publisher/subscriber, JSON payloads, topic wildcards.

4. GitHub proof (60 seconds)
   - Open ERICO-Projects and ERICO-Exercises.
   - Show README, reports folder, and one or two key files.

5. What I learned (40 seconds)
   - Clean code is not about making a task complicated.
   - It is about choosing the correct loop, function, class, data structure, and documentation style for the problem.

## Best recording method

Use a PPT or the report as the opening guide, then switch to GitHub/code. Do not spend the whole video reading code line by line. Explain the design decisions and show only the most important code snippets.
